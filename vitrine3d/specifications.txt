1. CASOS DE USO ESPERADOS (MVP)
================================================================================

UC-01  CADASTRO DE LOJISTA
  O lojista acessa a plataforma, preenche nome de usuário, nome da loja,
  e-mail, senha, número de WhatsApp e localização (estado/cidade) e cria
  sua conta. A senha é armazenada com hash BCrypt.

UC-02  GERENCIAMENTO DE CATEGORIAS
  O lojista cria categorias personalizadas para organizar seus produtos.
  O sistema também disponibiliza categorias globais pré-cadastradas
  (Animes, Pokémon, Jogos, etc.) visíveis para todos.

UC-03  CADASTRO DE PRODUTO
  O lojista cadastra produtos informando nome, descrição, material,
  dimensões, se é multicolorido, categoria e imagem. A imagem é enviada
  para o MinIO e a URL resultante é salva no produto.

UC-04  IMPORTAÇÃO VIA MAKERWORLD
  O lojista informa a URL de um modelo no MakerWorld. O sistema faz
  scraping da página via JSoup e extrai automaticamente título, descrição
  e imagem principal para pré-preencher o formulário de cadastro.

UC-05  VITRINE PÚBLICA
  O cliente acessa a vitrine de uma loja via navegador ou app mobile.
  A vitrine exibe os produtos com isVisible=true, organizados por categoria.
  O cabeçalho exibe as categorias da loja como menu dinâmico.

UC-06  FLUXO DE "COMPRA" VIA WHATSAPP
  O cliente clica em "Tenho interesse" em um produto. O sistema gera uma
  URL wa.me com o número do lojista e uma mensagem pré-preenchida contendo
  o nome do produto, redirecionando para o WhatsApp.

UC-07  SELEÇÃO DE LOCALIZAÇÃO NO CADASTRO
  O front-end consulta a API de localização para exibir dropdowns com todos
  os estados brasileiros e, ao selecionar um estado, as cidades daquele
  estado. O lojista escolhe onde está localizado.

UC-08  CONTROLE DE VISIBILIDADE DE PRODUTO
  O lojista pode ocultar ou exibir um produto sem precisar excluí-lo
  (campo isVisible). A vitrine pública exibe somente produtos visíveis.

4. O QUE FALTA PARA O DEPLOY
================================================================================

  OBRIGATÓRIO (bloqueante)
  -------------------------

  4.1  SEGURANÇA  ✓ CONCLUÍDO
       SecurityConfig, JWT e AuthController implementados.
       jwt.secret em application.properties ainda precisa ser
       externalizado como variável de ambiente antes do deploy (ver 4.2).

  4.2  EXTERNALIZAR CREDENCIAIS  (ainda pendente)
       O arquivo application.properties possui credenciais hardcoded.
       Para produção, substituir por variáveis de ambiente:

         spring.datasource.url=${DATABASE_URL}
         spring.datasource.username=${DATABASE_USER}
         spring.datasource.password=${DATABASE_PASSWORD}
         minio.endpoint=${MINIO_ENDPOINT}
         minio.access-key=${MINIO_ACCESS_KEY}
         minio.secret-key=${MINIO_SECRET_KEY}
         jwt.secret=${JWT_SECRET}

  4.3  POLÍTICA DE ACESSO PÚBLICO DO MINIO
       Os objetos enviados ao MinIO são privados por padrão. Para que as
       imagens dos produtos sejam acessíveis publicamente via URL, é
       necessário configurar a bucket policy como "public-read" ou
       usar URLs pré-assinadas com expiração.

  4.4  PERFIL DE PRODUÇÃO
       Criar application-prod.properties com:
         spring.jpa.hibernate.ddl-auto=validate  (não mais "update")
         spring.jpa.show-sql=false
       Usar Flyway ou Liquibase para migrações versionadas em vez de ddl-auto.

  RECOMENDADO (não bloqueante, mas importante)
  --------------------------------------------

  4.5  DOCKERFILE
       Criar Dockerfile para empacotar a aplicação como imagem Docker.
       Exemplo mínimo:
         FROM eclipse-temurin:17-jre
         COPY build/libs/vitrine3d-*.jar app.jar
         ENTRYPOINT ["java", "-jar", "/app.jar"]

  4.6  HTTPS / CERTIFICADO SSL
       Configurar HTTPS no servidor de produção (Nginx como reverse proxy
       com certificado Let's Encrypt, por exemplo).
       Após HTTPS, ajustar CorsConfig para listar origens explícitas
       em vez de "*" (recomendado com credentials).

  4.7  HEALTH CHECK E MONITORAMENTO
       Adicionar spring-boot-starter-actuator ao build.gradle:
         implementation 'org.springframework.boot:spring-boot-starter-actuator'
       Expor /actuator/health para verificação pelo orquestrador (Docker/K8s).

  4.8  CORS PARA DOMÍNIO DE PRODUÇÃO
       Trocar allowedOrigins("*") pelo domínio real do front-end para
       evitar consumo não autorizado da API.

  4.9  TESTES DE INTEGRAÇÃO
       Adicionar Testcontainers para executar testes contra PostgreSQL e
       MinIO reais em CI, garantindo que o seed do DataInitializer e
       as queries JPA funcionem no banco real.
